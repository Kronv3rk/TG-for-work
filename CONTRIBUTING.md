# Как вносить изменения

Проект — Android-порт схемы [`Flowseal/tg-ws-proxy`](https://github.com/Flowseal/tg-ws-proxy).
Основная ценность здесь — стабильность соединения на плохих сетях, поэтому к изменениям в
логике маршрутизации требования выше, чем к UI.

## Что нужно локально

- JDK 17
- Android SDK (`platforms;android-35`, `build-tools;35.0.0`)
- Gradle через wrapper — отдельная установка не нужна

Если SDK лежит не в стандартном месте, укажите путь через `ANDROID_SDK_ROOT` и примите лицензии.

## Проверки перед пушем

```bash
./gradlew :app:testDebugUnitTest
./gradlew :app:lintDebug
./gradlew :app:assembleDebug
```

Ровно эти три шага прогоняются в CI на каждый pull request. Если локально Android SDK нет,
допустимо положиться на CI, но тогда напишите об этом в описании PR.

## Ветки и коммиты

- `main` — стабильная ветка, релизы собираются только с неё.
- Работа ведётся в отдельных ветках: `feature/...`, `fix/...`, `chore/...`.
- Прямой пуш в `main` не используется, изменения приходят через pull request.
- Сообщение коммита — в повелительном наклонении и по делу:
  `Fix media stall on cellular reconnect`, а не `fixes`.
- Один коммит — одно осмысленное изменение.

## Pull request

Заполните [шаблон PR](.github/PULL_REQUEST_TEMPLATE.md): что изменилось, как проверялось,
что осталось за скобками. Отмечайте галочки только по фактически выполненным проверкам.

Для изменений в маршрутизации в описании полезно указать:

- на какой сети проверяли (Wi-Fi / мобильная);
- что происходит с медиа, а не только с текстовым чатом;
- как ведёт себя маршрут при обрыве и переподключении.

## Изменения в логике прокси

Код прокси лежит в `app/src/main/java/com/flowseal/tgwsproxy/proxy/`. Здесь действуют
дополнительные правила:

- новое поведение маршрутов, таймаутов и валидации покрывается юнит-тестом
  в `app/src/test/java/com/flowseal/tgwsproxy/proxy/`;
- изменения, перенесённые из upstream, отмечаются в [`docs/UPSTREAM_SYNC.md`](docs/UPSTREAM_SYNC.md)
  с указанием, что именно взято и что сознательно не портировано;
- не переносите десктоп-специфичные части upstream (упаковка, CLI, настройки окна) —
  они в этом порте не нужны.

## Версии и релизы

Версия задаётся в `app/build.gradle.kts` (`versionCode` и `versionName`). При релизе:

1. Поднимите `versionCode` и `versionName`.
2. Опишите изменения в README в разделе «Что нового».
3. Слейте PR в `main`.
4. Поставьте тег `vX.Y.Z` и запушьте его — `Android Release` соберёт и опубликует APK.

`versionCode` должен расти монотонно, иначе Android откажется ставить обновление поверх.

## Совместимость установленных сборок

Подпись APK менять нельзя без явной необходимости: Android не обновляет приложение поверх
версии, подписанной другим ключом, и показывает конфликт пакетов. Подробности — в
[SECURITY.md](SECURITY.md).
