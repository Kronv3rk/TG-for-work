# TG-for-work

Android-порт схемы Flowseal tg-ws-proxy для запуска локального MTProto proxy на телефоне.
Приложение открывает Telegram с готовой `tg://proxy` ссылкой, держит прокси в foreground service
и показывает постоянное уведомление с быстрыми действиями.

## Что нового в 1.8.4

Исправление сообщения Telegram «прокси использует некорректные настройки»:

- **Откат WebSocket-маршрута для DC без релея.** В 1.8.3 для DC1/DC3/DC5/203 подключение
  шло по имени `kwsN.web.telegram.org`. Оказалось, что web-релей Telegram обслуживает только
  DC2 и DC4 (их имена резолвятся в один и тот же адрес — как во встроенной карте), поэтому
  для остальных соединение устанавливалось, но рабочий MTProto-поток не шёл, и клиент считал
  прокси неисправным. Теперь WebSocket используется только для DC из карты редиректов или для
  адреса, заданного вручную в настройках.
- **Подсказка при смене ссылки.** Если изменить секрет, маскирующий домен, адрес или порт,
  сохранённый внутри Telegram прокси перестаёт подходить — и Telegram показывает ровно это
  сообщение. Теперь после сохранения приложение предлагает открыть Telegram с новой ссылкой.

## Что нового в 1.8.3

Маршрут WebSocket теперь доступен всем дата-центрам:

- **Раньше WS работал только для DC2 и DC4.** Для остальных (DC1, DC3, DC5, 203) во встроенной
  карте не было адреса, и маршрут молча пропускался — оставались только Cloudflare и прямой TCP.
  Теперь, если адреса в карте нет, подключение идёт по имени релея (`kwsN.web.telegram.org`),
  поэтому WebSocket доступен для всех DC.
- **Поддержка IPv6-сетей без хардкода адресов.** Подключение по имени резолвится системой,
  поэтому на IPv6-only мобильных сетях путь работает там, где жёстко зашитый IPv4 не отвечает.
- Приоритет прежний: свой оверрайд `DC:IP` → встроенная карта → имя релея. В журнале видно,
  какой хост реально использован.
- Встроенные адреса дата-центров сверены с актуальным `Flowseal/tg-ws-proxy` — совпадают
  полностью, менять их не потребовалось.

## Что нового в 1.8.2

Полный экран настроек — паритет с конфигом десктопного `tg-ws-proxy`:

- **Адрес и порт прокси** — если `1443` занят другим приложением, порт можно сменить,
  ссылка `tg://proxy` пересобирается автоматически.
- **Адреса дата-центров (`DC:IP`)** — свои адреса в формате `2:149.154.167.220 4:...`,
  как ключ `dc_ip` в оригинале. Оверрайд имеет приоритет над встроенной картой на всех
  маршрутах (WS, Worker и прямой TCP), поэтому нерабочий DC можно направить вручную.
- **Свой домен Cloudflare** (`kwsN.домен`) — раньше поле существовало, но не редактировалось.
- **Тюнинг производительности** — размер буфера (16–1024 КБ) и максимум одновременных
  соединений (16–512); значения ограничиваются безопасным диапазоном.
- Все поля проверяются перед сохранением: неверный секрет, домен, адрес, порт или пара
  `DC:IP` не сохранятся молча.
- **Строка сборки внизу экрана** — версия и отпечаток ключа подписи
  («TG for Work 1.8.2 · ключ D6:A9:66:D0»), чтобы видеть, какая сборка и какой ключ установлены.

## Что нового в 1.8.1

Прокси больше не засыпает в фоне:

- **Wake lock и Wi-Fi lock.** Пока прокси работает, приложение удерживает CPU и Wi-Fi-радио
  активными. Без этого Android усыплял процессор через несколько секунд после выключения
  экрана, блокирующие чтения сокетов замирали и соединение Telegram рвалось.
- **Тип foreground-сервиса `specialUse`** на Android 14+. С Android 15 сервис типа `dataSync`
  принудительно останавливается примерно через 6 часов в сутки — для постоянно включённого
  прокси это неприемлемо, поэтому используется тип без такого лимита.
- **Живучесть при смахивании из недавних** — `stopWithTask=false` плюс перезапуск сервиса
  в `onTaskRemoved` для агрессивных прошивок (MIUI и подобные).
- **Баннер «разрешить фоновую работу»** на главном экране: показывается, только если приложение
  не исключено из оптимизации батареи, и по нажатию открывает системный диалог. Там же подсказка
  про автозапуск для MIUI.

## Что нового в 1.8.0

Паритет с оригинальным `Flowseal/tg-ws-proxy` по обходу блокировок:

- **Свой Cloudflare Worker.** Приложение умеет использовать ваш собственный worker
  (`wss://<домен>/apiws?dst=<ip>&dc=<n>`) — сырой TCP-туннель к дата-центру, фронтящийся
  через Cloudflare. Это отдельный маршрут `CFW`, который пробуется первым, когда задан.
- **Экран настроек** (строка «Настройки» на главном экране): свой worker-домен (можно
  несколько через запятую), свой маскирующий домен Fake TLS и свой секрет с кнопками
  «Сгенерировать» и «Скопировать». Значения применяются на лету с перезапуском прокси.
- Маршрут `CFW` учитывается в ранжировании по стабильности, журнале и счётчиках.

## Что нового в 1.7.0

Релиз сфокусирован на стабильности Telegram — и чата, и мультимедиа — на нестабильных
и мобильных сетях:

- **Адаптивные таймауты маршрутов.** Маршрут, который только что отвалился, получает короткий
  бюджет на переподключение (~3с) вместо фиксированных 10с. Застрявшее медиа быстрее находит
  рабочий путь. Приём перенесён из upstream `tg-ws-proxy` (адаптивный 2с/10с таймаут).
- **WebSocket keepalive и детект мёртвого канала.** На простое прокси шлёт ping-кадры и отличает
  «реально мёртвое соединение» от «медленно, но качается большой медиа-кадр», поэтому здоровые
  медленные загрузки не рвутся, а зависшие на полуоткрытом сокете каналы (типичная беда сотовых
  сетей) recycled примерно за минуту.
- **Ограничение перебора Cloudflare-доменов.** Не более 3 доменов за одно соединение — устранён
  случай, когда полностью заблокированный пул CF перебирал десяток доменов и медиа висело
  десятки секунд.
- **Стееринг переподключений.** Если маршрут подключился, но не отдал ни байта, он уходит в
  cooldown, и следующий быстрый реконнект Telegram выбирает рабочий путь.
- **Выделенный поток приёма соединений** — новые подключения больше не голодают под нагрузкой медиа.
- **Журнал подключений со стабильностью и качеством.** Каждое подключение, отказ и сессия
  записываются с маршрутом, латентностью и объёмом данных. Журнал виден на главном экране
  (последние события, долгое нажатие — копирование целиком) и дублируется в Logcat
  (`adb logcat -s TgForWork`).
- **Маршруты ранжируются по измеренной стабильности.** Прокси постоянно измеряет долю успешных
  подключений и латентность каждого маршрута (WS/CF/TCP по каждому DC) и пробует сначала самый
  стабильный и быстрый, затем второй по качеству и так далее. Строка «Качество» на экране
  показывает текущие оценки.
- Обновлённый встроенный пул Cloudflare-доменов и живое обновление уведомления со статусом.
- Добавлены юнит-тесты ключевой логики маршрутизации и валидации; CI прогоняет их перед сборкой APK.

## Быстрый старт

Локально нужен установленный JDK 17, Android SDK и Gradle:

```bash
gradle :app:assembleDebug
```

Если SDK не настроен, укажите `ANDROID_SDK_ROOT` и примите лицензии Android SDK.

## Релизы через GitHub Actions

APK собирается в GitHub Actions и публикуется на странице Releases при пуше тега:

```bash
git tag v1.0.0
git push origin v1.0.0
```

Workflow также можно запустить вручную через Actions -> Android Release, указав тег вида `v1.0.0`.

Для signed release APK добавьте в GitHub repository secrets:

- `ANDROID_KEYSTORE_BASE64` - keystore `.jks`, закодированный в Base64
- `ANDROID_KEYSTORE_PASSWORD`
- `ANDROID_KEY_ALIAS`
- `ANDROID_KEY_PASSWORD`

Если signing secrets не настроены, workflow публикует debug-signed APK, пригодный для установки и тестирования.

Важно: debug-signed APK из разных GitHub Actions запусков может быть подписан разными ключами.
Android не обновляет приложение поверх версии с другой подписью и показывает конфликт пакетов.
Если вы уже установили такую сборку, удалите старое приложение один раз и установите новую версию.
Чтобы дальнейшие обновления ставились поверх старых, настройте постоянный release signing key через secrets.

## Google Play Защита

Предупреждение Play Защиты при установке вручную не отключается кодом приложения. Оно появляется,
когда APK не распространялся через Google Play и/или подписан debug-ключом, неизвестным Google.

Чтобы уменьшить такие предупреждения:

1. Собирайте release APK с постоянным signing key через secrets выше.
2. Не меняйте signing key между версиями.
3. Для полного устранения предупреждений публикуйте приложение через Google Play или используйте проверенный корпоративный канал распространения.

## Возможности APK

- локальный MTProto proxy на `127.0.0.1:1443`;
- Fake TLS secret `ee...` с маскирующим доменом по умолчанию;
- Cloudflare fallback по списку доменов из оригинального `Flowseal/tg-ws-proxy`;
- прямой TCP fallback к Telegram DC, если WebSocket/Cloudflare недоступны;
- автоматический выбор маршрута: приложение пробует разные схемы и временно пропускает те, которые недавно не ответили;
- отдельный порядок для мобильной сети и медиа: Cloudflare пробуется раньше, чтобы картинки и видео быстрее находили рабочий путь;
- постоянное Android-уведомление: открыть Telegram, скопировать ссылку, остановить прокси;
- интерактивный UI: запуск, проверка, копирование, перезапуск, переключатели Fake TLS и Cloudflare.
- обновлённый пульт управления в версии `1.6.0`: крупный статус, живой маршрут, быстрые действия и отдельная зона диагностики.

## Возврат к старому UI

Перед редизайном сохранена точка возврата:

- ветка `backup/v1.5.0-before-ui-redesign`;
- тег `backup-v1.5.0-before-ui-redesign`.

Если новый интерфейс не подойдёт, можно вернуться к состоянию версии `1.5.0` через эту ветку или тег.

## Маршруты и обход блокировок

Приложение не держится за один способ подключения. Для каждого Telegram DC оно выбирает порядок маршрутов
по сети и типу трафика:

- Wi-Fi, обычный трафик: WebSocket -> Cloudflare -> прямой TCP;
- Wi-Fi, медиа: Cloudflare -> WebSocket -> прямой TCP;
- мобильная сеть: Cloudflare -> TCP -> WebSocket;
- медиа через Cloudflare включается раньше, потому что изображения и видео часто хуже проходят через прямой путь.

Если маршрут не ответил, он попадает в короткий cooldown. Следующая попытка идёт через другой способ,
а экран показывает активный маршрут, тип сети и счётчики WS/CF/TCP.

## Использование Android APK

1. Установите APK из Releases.
2. Откройте приложение и нажмите `Открыть Telegram`.
3. Telegram должен открыть экран подключения MTProto proxy.
4. Подтвердите прокси `127.0.0.1:1443`.
5. Не убирайте постоянное уведомление, если хотите держать прокси активным в фоне.

Если Telegram не открылся автоматически, нажмите `Скопировать`, отправьте ссылку себе в Telegram и откройте её из клиента.

На Android нет desktop tray, поэтому его роль выполняет foreground notification.
