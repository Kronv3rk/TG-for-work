# Порт 80 для Cloudflare Proxy и Worker

Оригинальный `Flowseal/tg-ws-proxy` поддерживает опцию `--no-secure`:
соединения с Cloudflare Proxy и собственным Cloudflare Worker по WebSocket
открываются на **TCP-порту 80 без TLS**.

В TG-for-work аналогичный режим включается в настройках:
**«Cloudflare без TLS (порт 80)»**. По умолчанию он выключен.

## Что меняется

- Cloudflare Proxy WebSocket и собственный Cloudflare Worker используют
  `ws://` по порту 80 вместо `wss://` по порту 443.
- Для Worker это относится и к прогретым соединениям Wi-Fi-пула.
- Прямые WebSocket-соединения к Telegram, опциональный Domain Fronting и
  экспериментальный HTTP/2 продолжают работать через TLS.
- Переключение режима пересоздаёт локальный прокси, как и прочие
  настройки транспорта.

## Ограничения и риски

Соединение без TLS позволяет провайдеру сети и промежуточным узлам
просматривать адреса, заголовки и структуру передаваемых кадров,
отслеживать подключения и вмешиваться в них. Внутреннее шифрование
MTProto не заменяет аутентификацию удалённого TLS-сервера.

Включайте режим только если он необходим для конкретного сетевого
окружения. Для обычного подключения рекомендуется оставлять TLS.
Некоторые серверы и сети блокируют WebSocket Upgrade по порту 80;
в этом случае приложение может выбрать другой доступный маршрут.

Автоматические JVM-тесты проверяют политику маршрута и отсутствие
случайного отключения TLS у Domain Fronting. Совместимость реальных
Cloudflare-сервисов на порту 80 пока требует отдельной проверки.
