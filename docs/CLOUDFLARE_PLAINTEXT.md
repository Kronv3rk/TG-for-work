# Транспорт Cloudflare

По умолчанию TG-for-work сначала проверяет WebSocket с TLS на порту 443.
При тайм-ауте приложение может использовать WebSocket на порту 80 без
внешнего TLS. Для выбора рабочего домена проверяются до шести кандидатов
двумя группами по три. При смене сети оценки маршрутов сбрасываются.

Настройка «Разрешить резервный Cloudflare без TLS» доступна в расширенных
настройках. Она включена по умолчанию, если пользователь ещё не выбирал
этот параметр. Явный запрет сохраняется при обновлении.

Ручной режим «Cloudflare без TLS (порт 80)» соответствует опции
`--no-secure` оригинала и распространяется на Cloudflare Proxy и собственный
Worker. Он выключен по умолчанию. Автоматический резервный режим
действует только для публичного Cloudflare Proxy. Прямой Telegram
WebSocket, Domain Fronting и HTTP/2 продолжают использовать TLS.
Ошибка проверки сертификата сама по себе не является основанием
для переключения.

## Риски

Без внешнего TLS сетевые посредники могут видеть адреса, заголовки,
структуру кадров и вмешиваться в обмен. Шифрование MTProto не заменяет
проверку подлинности удалённого TLS-сервера. Выбранный публичный
транспорт обозначается «CF TLS» или «CF без TLS».

Если необходима обязательная защита внешнего соединения, выключите
оба режима без TLS. Приложение не отключает проверку сертификатов.

## Испытания

25 ноября 2026 года независимый MTProto-клиент через Android-прокси
обменялся ключами с DC2 и DC4 и получил корректные ответы на ping.
На API 35 проверено восстановление после имитации смены Wi-Fi и мобильной
сети. На API 37 первоначальный сбой DC4 не повторился после добавления
второй группы кандидатов. Это не подтверждает доступность всех доменов
на всех сетях или передачу медиафайлов.
