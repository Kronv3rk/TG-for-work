# Тестовые дата-центры Telegram

Приложение поддерживает тестовое окружение Telegram по сетевому протоколу
оригинального `Flowseal/tg-ws-proxy` 1.11.4.

## Автоматическое определение

Когда Telegram передаёт номер дата-центра с прибавленными 10000
(`10001`–`10003`), прокси сам распознаёт тестовое окружение.
Обычный и тестовый аккаунты могут работать одновременно через один прокси.
Для тестовых дата-центров используются другие IP-адреса и путь
`/apiws_test` вместо `/apiws`.

## Принудительный режим

Если используемый клиент (например, библиотека для разработки Telegram-клиента)
передаёт тестовые дата-центры как обычные номера `1`–`3`, в настройках
есть переключатель **«Только тестовые дата-центры Telegram»**.
Он выключен по умолчанию. При его включении обычный аккаунт перестанет
подключаться через этот прокси: все номера дата-центров направляются
в тестовое окружение. После окончания испытаний выключите опцию.

## Сетевые маршруты

Для тестовых дата-центров допускаются собственный Cloudflare Worker,
WebSocket с отдельным путём `/apiws_test` (если для дата-центра есть
прямой веб-релей) и прямой TCP к тестовому IP.

Обычный публичный Cloudflare Proxy и HTTP/2-медиа к производственной
инфраструктуре не используются для тестового окружения. Тестовые
соединения намеренно не помещаются в обычный Wi-Fi-пул WebSocket/Worker,
чтобы тестовый и производственный трафик не смешивались. Это
адаптация оригинального механизма к ресурсным ограничениям Android.

| Дата-центр | IP тестового окружения |
| --- | --- |
| 1 | `149.154.175.10` |
| 2 | `149.154.167.40` |
| 3 | `149.154.175.117` |

Автоматизированные JVM-тесты проверяют распознавание номеров, выбор
адресов и исключение производственных Cloudflare-маршрутов.
Работа с реальными тестовыми серверами Telegram требует отдельной
интеграционной проверки.
