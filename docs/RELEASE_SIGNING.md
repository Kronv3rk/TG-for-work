# Подпись релизов

Начиная с версии 2.0.0 используется новая закрытая пара ключей. Старый
резервный ключ находился в публичном репозитории; он не должен применяться
для новых выпусков. Если Android отклоняет обновление из-за смены подписи,
удалите старую версию и установите APK из официального GitHub Releases.
Перед удалением при необходимости запишите параметры прокси; после установки
откройте Telegram с новой ссылкой. Все следующие релизы должны иметь один
и тот же новый сертификат. Не устанавливайте APK из сторонних источников.

## Настройка владельцем

Создайте среду GitHub Actions `android-release`. Разрешите развёртывание только
из ветки `main`; включите защиту этой ветки, ограничения создания тегов и
проверку выпуска владельцем, если тариф и настройки репозитория позволяют.
Не размещайте закрытый ключ в Git, артефактах, переписке или логах.

Для среды задайте четыре секрета: `TG_RELEASE_KEYSTORE_BASE64`,
`TG_RELEASE_KEYSTORE_PASSWORD`, `TG_RELEASE_KEY_ALIAS`,
`TG_RELEASE_KEY_PASSWORD`. Отдельная переменная среды
`TG_RELEASE_CERT_SHA256` содержит публичный SHA-256 отпечаток сертификата
без двоеточий. Сохраните зашифрованную резервную копию нового keystore
и паролей в независимом защищённом хранилище владельца.
Не используйте прежние ANDROID_KEYSTORE_* секреты.

Выпуск запускается вручную из Actions → Android Release с тегом версии,
совпадающим с versionName. Ветка main должна содержать номер версии,
возрастающий versionCode и release-notes/<тег>.md. Сначала выполняются
тесты, Lint и сборка без ключа. Подпись выполняется отдельным заданием,
не запускающим Gradle и не извлекающим исходный код. Без полного набора
секретов или при несовпадении сертификата публикация невозможна.
GitHub Release содержит подписанный APK, SHA-256 файла и отпечаток сертификата.

Удаление старого ключа из текущей ветки не удаляет его из истории,
форков или уже скачанных копий. Не переписывайте историю без отдельного
плана согласования; новая пара ключей является основным способом
устранения риска.
