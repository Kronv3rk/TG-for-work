# Приёмка HTTP/2 и сравнение с оригиналом

Стенд проверяет Android-порт TG-for-work относительно сетевого поведения
`Flowseal/tg-ws-proxy` v1.11.4. Исходная база для сверки:
`docs/UPSTREAM_PARITY.md`.

## Что проверяется автоматически

**Локальная лаборатория** запускается для изменений сетевых файлов в `main`
или вручную через GitHub Actions → **HTTP/2 acceptance lab**.
Выполняются JVM-тесты с реальным TLS-соединением и ALPN HTTP/2 к
локальному `MockWebServer`. Они проверяют передачу бинарного MTProto,
отказ от HTTP/1.1 downgrade, повтор и подавление позднего ответа,
сохранение принятых ответов при последующей ошибке, 403/429,
ограничения памяти и освобождение слотов, а также недопустимые размеры
исходящих пакетов. Отдельно проверяются сценарии построения отчётов
и обработки статистики.

Отчёты JUnit/XML и HTML доступны как GitHub Actions artifact
`h2-local-acceptance`. Для локального запуска:

```bash
./gradlew --no-daemon :app:testDebugUnitTest --tests 'com.flowseal.tgwsproxy.proxy.CfH2TransportTest'
python3 -m unittest discover -s scripts/tests -p 'test_*.py'
```

**Проверка настоящего публичного узла** запускается **только вручную**.
В GitHub Actions выберите `HTTP/2 acceptance lab`, нажмите
`Run workflow` и укажите `h2_host`: полное доменное имя конкретного
узла `kws<номер-дата-центра>.<домен Cloudflare Proxy>`, без `https://`,
порта, пути, параметров или учётных данных. Пустое поле означает только
локальные испытания. Настройка в секретах GitHub не требуется.

В этом режиме:
1. Python `httpx[http2]==0.28.1` (версия клиента из оригинала) и
   Android-совместимый `OkHttp` выполняют по одному `HEAD /api`
   на **один и тот же** указанный узел.
2. Оба клиента обязаны подтвердить HTTPS/TLS-сертификат и ALPN `h2`,
   а ответ HEAD должен иметь код `2xx`, `405` или `501`.
   Перенаправления не принимаются.
3. В `h2-public-preflight` сохраняются `httpx.json`, `okhttp.json`,
   `comparison.json`, XML и HTML тестов. Сравниваются статус и время
   одного запроса. Эти разовые задержки **не являются** замерами скорости.

**Граница доказательства:** HEAD /api проверяет доступность и
HTTP/2-согласование. Даже если оба клиента прошли проверку, это **не**
доказывает, что реальный Cloudflare `POST /api` правильно обменивается
MTProto-медиапакетами, и не подтверждает работу на Android-устройстве.
Инструмент намеренно не отправляет Telegram-пакеты, секреты и данные
пользователя на произвольные домены.

## Полевое испытание на Android

Когда появится телефон с установленным подписанным приложением, можно
запустить безопасный сбор агрегированной статистики с компьютера:

```bash
python3 scripts/android_field_sample.py --minutes 30 --interval 15 --output acceptance-report/ws-wifi.csv
```

Телефон должен быть подключён к `adb`; если устройств несколько,
добавьте `--serial <номер из adb devices>`. Скрипт ничего не
устанавливает, не переключает Wi-Fi/LTE, не трогает экран и не
читает `logcat`, сообщения или содержимое пакетов. Он записывает только
время, наличие процесса, общую PSS-память, уровень заряда и температуру
батареи, если эти данные доступны. Нулевое или отсутствующее значение
в отчёте нельзя трактовать как отсутствие утечек.

Для сопоставления с оригиналом нужно на одинаковой сети провести
несколько повторов одинакового сценария загрузки/передачи медиа:
прямой TCP, WebSocket, Cloudflare Worker, экспериментальный H2, затем
сценарии Wi-Fi ↔ LTE, блокировка экрана и длительная работа. Фиксировать
длительность, размер и скорость передачи, количество переподключений,
ошибки и ресурсные показатели. H2 включать вручную; по умолчанию он
останется выключенным до подтверждения стабильности.

## Журнал принятия решений

| Возможность | Подтверждение | Решение |
| --- | --- | --- |
| Локальные HTTP/2-запросы и ошибки | JUnit/MockWebServer TLS/ALPN | Принимается после зелёного CI |
| Согласование с настоящим Cloudflare | Совместные HEAD-пробы httpx/OkHttp | Пока без адреса и результатов не подтверждено |
| Настоящий обмен MTProto через Cloudflare POST /api | Тестовый контролируемый узел и соединение Telegram | Не подтверждено |
| Fake TLS, тестовые дата-центры, Domain Fronting | Реальные серверы + устройство Android | Не подтверждено |
| Стабильность, расход ресурсов и батареи | Серии воспроизводимых испытаний с `adb` | Не подтверждено |
| Включение H2 по умолчанию | Успешные испытания выше | Запрещено до подтверждения |

Включение HTTP/2 по умолчанию не является автоматическим следствием
прохождения GitHub CI. До результатов полевых испытаний это отдельное
решение по выпуску.
