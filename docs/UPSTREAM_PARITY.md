# Технологическое соответствие TG-for-work оригиналу

Дата повторной сверки: 10 ноября 2026 года. Оригинал —
[Flowseal/tg-ws-proxy](https://github.com/Flowseal/tg-ws-proxy),
релиз **1.11.4**, основная ветка проверена до коммита `6690b788432f`
(6 ноября 2026 года). В Android опубликована версия **1.11.3**;
следующий пакет соответствия готовится к выпуску как **1.11.4**
(исправления из PR № 40–41).

**Критерий полного соответствия:** реализованы все применимые к Android сетевые механизмы оригинала, функционально совместимы с его действующими серверными конечными точками; есть модульные, интеграционные и полевые доказательства работоспособности. Различия Android (жизненный цикл, радиомодуль, системное хранилище сертификатов) не требуют копировать десктопную реализацию. Отсутствие доказательств нельзя подменять наличием исходного кода.

## Оставшиеся обязательные испытания

1. **Совместимость с реальным Cloudflare `/api`:** проверить, что HTTP/2-POST действительно принимается существующими узлами, и сравнить скорость с WebSocket и прямым TCP на одной сети.
2. **Маскировка Fake TLS:** сравнить записи TLS и ответы с живым маскирующим сайтом, включая SNI, cipher suites, гибридный key_share и задержку ответа; проверить сборки Android с различными поставщиками TLS.
3. **Нагрузочная устойчивость:** многочасовая загрузка больших медиафайлов, повторные запросы на нестабильном канале, ограничение памяти и восстановление после смены Wi-Fi/LTE.
4. **Поведение фонового сервиса:** выключенный экран, энергосбережение и ограничения Android от версии 7 до последних API. Проверить работу без интернета для самого локального listener и после восстановления сети.
5. **Маршрутизация и domain fronting:** испытать исправление реальных ошибок DPI/SNI без выключения штатной проверки сертификата на обычных маршрутах.
6. **Решение по умолчанию для H2:** включать только после успешных полевых испытаний; в противном случае сохранять opt-in и честно фиксировать отличие.
7. **Test DC:** проверить автоматическое распознавание +10000 и принудительный режим через реальные тестовые серверы Telegram; модульная проверка маршрутов уже выполнена.
8. **PROXY protocol v1:** проверить приём прямых TCP4/TCP6-подключений через реальный доверенный NGINX/HAProxy, с выключенным режимом проверить сохранение обычного MTProto listener.
9. **Cloudflare без TLS:** проверить реальный WebSocket Upgrade по порту 80 для Cloudflare Proxy и собственного Worker и убедиться, что без опции всегда используется TLS/443; H2 и Domain Fronting по-прежнему защищены.

## Обязательные правила выпуска

- Сохранять `applicationId`, формат `tg://proxy`, сохранённый секрет и действующий сертификат APK.
- Не менять согласованную действующую схему хранения ключа подписи без отдельного решения пользователя.
- Не утверждать «полное технологическое соответствие», пока отсутствуют полевые доказательства и явно отмеченные несоответствия.
- Для каждой последующей версии оригинала пересверять список изменений, заносить новую строку в этот документ и добавлять регрессионные тесты до изменений кода.
