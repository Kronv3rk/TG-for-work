# Безопасность

## Поддерживаемые версии

Исправления выпускаются только для последнего релиза из [Releases](../../releases).
Перед сообщением о проблеме проверьте, что она воспроизводится на актуальной версии.

## Как сообщить об уязвимости

Не заводите публичный issue для уязвимостей. Используйте
[Security advisories](../../security/advisories/new) — приватный черновик виден только
владельцу репозитория.

В отчёте полезны: версия приложения, устройство и версия Android, тип сети, шаги
воспроизведения и, если применимо, журнал подключений.

## Модель угроз

Приложение поднимает локальный MTProto proxy на `127.0.0.1:1443` и передаёт трафик Telegram
через WebSocket, Cloudflare-домены или прямой TCP к DC. Из этого следует:

- прокси слушает только loopback и не предназначен для приёма подключений извне устройства;
- маскирующий домен Fake TLS и пул Cloudflare-доменов — средство обхода блокировок,
  а не средство усиления шифрования; сквозное шифрование обеспечивает сам протокол Telegram;
- список Cloudflare-доменов может обновляться из сети, поэтому загруженные значения проходят
  валидацию, а при пустом или подозрительно коротком ответе активный пул сохраняется;
- журнал подключений содержит маршруты, латентность и объёмы данных. Секретов там нет,
  но перед публикацией журнала в issue просмотрите его.

## Подпись релизов

По умолчанию release-APK подписывается постоянным ключом, который **закоммичен в репозиторий**
(`app/signing/release-keystore.b64`), а его пароль указан открытым текстом в
`.github/workflows/android-release.yml`.

Это осознанный компромисс: он даёт устанавливаемые «поверх» обновления без настройки secrets,
но означает, что ключ не является секретом. Любой, у кого есть доступ к репозиторию, может
собрать APK, который Android примет как обновление этого приложения. Ключ подходит для
распространения сборок «для своих» и не подходит для публикации в Google Play.

Чтобы перейти на закрытый ключ, задайте в repository secrets все четыре значения:

- `ANDROID_KEYSTORE_BASE64`
- `ANDROID_KEYSTORE_PASSWORD`
- `ANDROID_KEY_ALIAS`
- `ANDROID_KEY_PASSWORD`

Workflow использует их вместо закоммиченного ключа. Частично заданный набор — ошибка сборки,
чтобы релиз не ушёл случайно подписанным запасным ключом.

Важно: смена ключа ломает обновление поверх уже установленных сборок. Пользователям придётся
один раз удалить старое приложение. Планируйте переход на отдельный релиз и предупреждайте
в описании релиза.

## Секреты в репозитории

Кроме описанного выше keystore, секретов в репозитории быть не должно. `.gitignore` исключает
`local.properties`, `*.jks`, `*.keystore` и `google-services.json`. Учётные данные для сборки
и публикации передаются только через GitHub secrets.
